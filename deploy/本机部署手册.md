# 校园二手交易平台本机部署手册

本文所有命令都以**工程根目录**为当前目录，并在 Windows PowerShell 中执行。
首次部署建议按顺序执行，不要跳过成功判据。

## 1. 前置检查

### 执行

```powershell
docker version
docker compose version
java -version
node --version
npm --version
```

### 成功判据

- Docker Desktop 正在运行；
- Docker Compose 能输出版本；
- Java 主版本为 17；
- Node.js、npm 能输出版本。

### 常见失败

- `docker` 无法连接：启动 Docker Desktop，等待 Engine 状态为 Running；
- 找不到 `java`：安装 JDK 17，并设置 `JAVA_HOME` 或把 `java.exe` 加入 PATH；
- 找不到 `node` 或 `npm`：安装 Node.js，重新打开 PowerShell。

## 2. 创建并修改本机环境配置

### 执行

```powershell
Copy-Item deploy\.env.example deploy\.env
notepad deploy\.env
```

至少修改：

```dotenv
CT_DB_PASSWORD=本机 MySQL root 密码
CT_JWT_SECRET=一段足够长的随机字符串
```

如果使用 Compose 创建 MySQL，确认以下两项一致：

```dotenv
MYSQL_ROOT_PASSWORD=...
CT_DB_PASSWORD=...
```

### 成功判据

```powershell
Test-Path deploy\.env
```

输出为 `True`，并且密码没有继续使用不安全的示例值。

### 常见失败

- 找不到文件：确认当前目录是工程根目录；
- 后端连不上 MySQL：检查 `CT_DB_HOST`、`CT_DB_PORT`、用户名和密码；
- 两个数据库密码不一致：让 `MYSQL_ROOT_PASSWORD` 与 `CT_DB_PASSWORD` 使用同一个值。

## 3. 检查并准备 MySQL、Redis

### 3.1 检查已有容器

```powershell
docker ps -a
docker port ct-mysql
docker port ct-redis
```

如果已经存在并运行：

```text
ct-mysql -> 3306
ct-redis -> 6379
```

就**不要**启动 `deploy/docker-compose.yml` 中的 MySQL、Redis，直接复用已有容器。

### 3.2 检查已有 MySQL 数据库和时区

```powershell
docker exec -it ct-mysql mysql -uroot -p -NBe "SHOW DATABASES LIKE 'campus_trade';"
docker exec -it ct-mysql mysql -uroot -p -NBe "SELECT @@global.time_zone, @@session.time_zone, CURRENT_TIMESTAMP, UTC_TIMESTAMP;"
```

输入 MySQL root 密码。

### 成功判据

- 第一条命令输出 `campus_trade`；
- `CURRENT_TIMESTAMP` 与 `UTC_TIMESTAMP` 相差 8 小时；
- 推荐看到 `+08:00`，如果显示 `SYSTEM`，也必须确认实际时间相差 8 小时。

如果数据库尚未初始化，可以在确认没有业务数据后执行：

```powershell
docker cp deploy\sql\init.sql ct-mysql:/tmp/init.sql
docker cp deploy\sql\initial-data.sql ct-mysql:/tmp/initial-data.sql
docker exec -it ct-mysql mysql -uroot -p campus_trade -e "source /tmp/init.sql; source /tmp/initial-data.sql"
```

### 3.3 没有已有容器时启动 MySQL、Redis

确认 3306、6379 未被占用后执行：

```powershell
docker compose --env-file deploy\.env --profile production -f deploy\docker-compose.yml up -d mysql redis
```

### 常见失败

- 端口已占用：不要删除占用端口的容器，优先按 3.1 复用；
- MySQL 没有 `campus_trade`：确认初始化脚本已执行；
- 时区不是 +08:00：先停止部署，修正 MySQL 部署时区后再启动后端。不要在业务 SQL 中添加时区补丁。

## 4. 启动独立 RocketMQ

RocketMQ 已从 `deploy/` 独立到工程根的 `rocketmq/` 目录。它包含：

```text
rocketmq/docker-compose.yml
rocketmq/broker.conf
```

### 执行

```powershell
docker compose --env-file deploy\.env -f rocketmq\docker-compose.yml up -d
```

首次启动会下载 `apache/rocketmq:5.3.2`，镜像较大，请等待命令完成。

### 成功判据

```powershell
docker ps -a --filter name=campus-trade
docker inspect campus-trade-rocketmq-permissions --format "{{.State.Status}} {{.State.ExitCode}}"
docker inspect campus-trade-topic-init --format "{{.State.Status}} {{.State.ExitCode}}"
```

应看到：

```text
campus-trade-namesrv   Up
campus-trade-broker    Up
campus-trade-proxy     Up
rocketmq-permissions   exited 0
topic-init             exited 0
```

检查 Topic：

```powershell
docker logs campus-trade-topic-init
docker exec campus-trade-broker sh mqadmin topicList -n namesrv:9876
```

日志中应包含：

```text
topicName=campus_trade_order_timeout
attributes={+message.type=DELAY}
```

### 常见失败

- 端口 9876、10911、10912 或 8081 被占用：检查 `docker ps -a` 和
  `netstat -ano`，停止冲突的非业务容器后重试；
- broker 退出：检查 `docker logs campus-trade-broker`，重点确认
  `rocketmq-permissions` 已经 `exited 0`；
- Topic 不存在：检查 `docker logs campus-trade-topic-init`，确认 broker
  已注册后再次执行 `up -d`；
- 不要手工把 Topic 建成 NORMAL 类型；应修复 init 服务或其依赖顺序。

## 5. 构建后端和前端

前端 `dist` 不提交到 Git，由用户在本机自行构建。

### 执行

```powershell
.\deploy\build.ps1
```

该脚本依次执行：

```text
backend\mvnw.cmd -B clean package -DskipTests
npm ci
npm run build
```

第一次运行 Maven Wrapper 会下载 Maven 和依赖，可能需要较长时间。

### 成功判据

```powershell
Test-Path backend\target\*.jar
Test-Path frontend\dist\index.html
```

均应为 `True`。

### 常见失败

- Maven 下载失败：检查网络、代理和 Maven Central 可达性；
- 找不到 JDK：确认 `java -version` 为 17；
- npm 安装失败：删除未完成的 `frontend\node_modules` 后重试；
- 前端构建失败：先执行 `npm ci`，再执行 `npm run build` 查看具体错误。

## 6. 启动后端

如果本机已有 `ct-mysql`、`ct-redis`，不要使用会重复启动依赖的
`deploy\start.ps1`，按本节手动启动后端。

### 导入环境变量

```powershell
Get-Content deploy\.env | ForEach-Object {
    if ($_ -match '^\s*#' -or $_ -notmatch '=') { return }
    $name, $value = $_ -split '=', 2
    [Environment]::SetEnvironmentVariable($name.Trim(), $value.Trim(), 'Process')
}
$env:CT_PROFILE = 'prod'
New-Item -ItemType Directory -Path $env:CT_UPLOAD_DIR -Force | Out-Null
```

### 启动 JAR

```powershell
java -Duser.timezone=Asia/Shanghai `
  -jar (Get-ChildItem backend\target\*.jar |
    Where-Object { $_.Name -notlike '*-sources.jar' -and $_.Name -notlike '*-plain.jar' } |
    Select-Object -First 1).FullName
```

### 成功判据

另开一个 PowerShell 窗口执行：

```powershell
curl.exe http://127.0.0.1:8080/api/actuator/health
```

应返回：

```json
{"status":"UP"}
```

### 常见失败

- 8080 被占用：执行 `netstat -ano | findstr :8080`，停止冲突进程；
- 数据库连接失败：检查 `CT_DB_*`；
- Redis 连接失败：检查 `CT_REDIS_*`；
- RocketMQ 连接失败：确认 Proxy 在 8081，且
  `CT_ROCKETMQ_ENDPOINTS=127.0.0.1:8081`。

## 7. 启动 nginx 容器

确认第 5 步已经生成 `frontend\dist`，并且后端已在 8080 运行。

```powershell
docker compose --env-file deploy\.env --profile production -f deploy\docker-compose.yml up -d nginx
```

### 成功判据

```powershell
docker ps --filter name=campus-trade-nginx
curl.exe -I http://localhost/
curl.exe http://localhost/api/actuator/health
```

应看到 nginx 为 `Up`、首页 HTTP 200，健康检查返回 `{"status":"UP"}`。

## 8. 访问验证

```powershell
curl.exe -I http://localhost/
curl.exe http://localhost/api/actuator/health
```

登录接口使用 `account` 字段：

```powershell
curl.exe -X POST http://localhost/api/auth/login `
  -H "Content-Type: application/json" `
  -d '{"account":"admin001","password":"Campus@2026"}'
```

测试账号来自 `deploy/sql/initial-data.sql`：

```text
管理员：admin001 / Campus@2026
学生：20230001 至 20230012 / Campus@2026
```

## 9. 黄金路径演示

使用浏览器访问 `http://localhost/`，按以下顺序演示：

1. 学生注册或使用已有学生账号登录；
2. 发布商品；
3. 管理员登录并审核商品；
4. 学生浏览商品并下单；
5. 卖家或交易双方确认订单；
6. 完成交易；
7. 买家评价；
8. 创建纠纷，管理员处理纠纷；
9. 返回订单详情确认状态、日志和评价结果。

涉及管理员操作时使用：

```text
admin001 / Campus@2026
```

## 10. 查看后端和 RocketMQ 证据

后端手动启动时，日志直接显示在当前 PowerShell；脚本启动时查看：

```powershell
Get-Content "$env:TEMP\campus-trade-backend.out.log" -Wait
Get-Content "$env:TEMP\campus-trade-backend.err.log" -Wait
```

RocketMQ 日志：

```powershell
docker logs campus-trade-namesrv
docker logs campus-trade-broker
docker logs campus-trade-proxy
docker logs campus-trade-topic-init
```

订单超时消息先按订单 Key 查询：

```powershell
docker exec campus-trade-broker sh mqadmin queryMsgByKey `
  -n namesrv:9876 `
  -t campus_trade_order_timeout `
  -k order-订单ID
```

拿到 Message ID 后查询完整属性：

```powershell
docker exec campus-trade-broker sh mqadmin queryMsgById `
  -n namesrv:9876 `
  -t campus_trade_order_timeout `
  -i 消息ID
```

延迟消息应能看到：

```text
TIMER_ENQUEUE_MS
TIMER_DELIVER_MS
TIMER_DEQUEUE_MS
```

订单状态应从待确认变为超时关闭，库存恢复，并写入
`超时自动关闭订单` 日志。

## 11. 停止服务

停止后端进程后执行：

```powershell
.\deploy\stop.ps1
```

如果后端是手动启动的，先在其 PowerShell 窗口按 `Ctrl+C`。

### 成功判据

```powershell
docker ps --filter name=campus-trade
```

RocketMQ、nginx 和本项目 Compose 容器均停止；已有的 `ct-mysql`、
`ct-redis` 不应被删除。不要使用 `docker compose down -v`，以免删除数据卷。
