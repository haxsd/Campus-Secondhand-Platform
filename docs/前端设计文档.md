# 校园二手交易平台 · 前端设计文档

> 配合 `docs/API接口文档.md`（接口契约，字段以它为准）使用。本文档定义前端的目录结构、路由、页面、状态管理和开发规范——给开发者（含 AI 辅助）的施工图。

## 1. 技术栈与全局约定

- Vue 3（组合式 API `<script setup>`，不用 Options API）+ Vite + JavaScript（不用 TS）
- Element Plus（全量引入即可，学习项目不做按需优化）+ Pinia + Vue Router + Axios
- 所有 ID/订单号按**字符串**处理，绝不 parseInt
- 金额展示统一 `¥xx.xx`；时间后端给的就是 `yyyy-MM-dd HH:mm:ss` 字符串，直接展示
- 状态展示一律走 `src/constants/` 的映射，不在页面里写死中文
- 每个页面只做该页的事，跨页共享数据放 Pinia，一次性传参用路由 query/params

## 2. 目录结构

```text
src/
├── main.js               挂载 App、注册 ElementPlus/Pinia/Router
├── App.vue               全局布局：顶栏 + <router-view>
├── api/                  接口层（唯一发请求的地方，页面不直接用 axios）
│   ├── auth.js  product.js  order.js  review.js  dispute.js
│   ├── history.js  category.js  file.js  admin.js
├── mock/                 mock 数据（与 api/ 同名文件一一对应）
│   └── auth.js  product.js  order.js  ...
├── constants/index.js    状态枚举映射 + 通用常量
├── stores/
│   └── user.js           登录态（token、用户信息）
├── router/index.js       路由 + 守卫
├── utils/
│   └── request.js        Axios 实例
├── components/           跨页面复用组件
│   ├── ProductCard.vue   商品卡片（列表/浏览记录共用）
│   ├── OrderStatusTag.vue 订单状态标签（颜色+文案）
│   ├── ImageUploader.vue 图片上传（发布商品/纠纷证据共用）
│   └── Pagination.vue    分页封装（可选，el-pagination 直接用也行）
└── views/                页面（见第 4 节）
```

## 3. 基础件设计

### 3.1 utils/request.js

```text
- axios.create({ baseURL: '/api', timeout: 10000 })
- 请求拦截器：从 user store 取 token，有则加 Authorization: Bearer <token>
- 响应拦截器：
    - HTTP 200 且 body.code === 0 → 直接 resolve(body.data)（页面拿到的就是 data）
    - body.code === 401 或 HTTP 401 → 清空登录态，ElMessage 提示，跳 /login（带 redirect 参数）
    - 其他 code → ElMessage.error(body.message)，reject
- 导出的函数签名：get(url, params) / post(url, data) / put(url, data) / del(url)
```

### 3.2 mock 机制

```text
- .env.development 中 VITE_USE_MOCK=true
- api/ 里每个函数模式固定：
    export function login(data) {
      if (useMock) return mockLogin(data)        // 来自 src/mock/auth.js
      return post('/auth/login', data)
    }
- mock 函数返回 Promise（setTimeout 300ms 模拟延迟），数据字段严格按 API 文档
- mock/order.js 必须造出 6 种订单状态各至少 1 单（0~5），方便页面全状态联测
- mock/product.js 造 20+ 条商品（覆盖多分类/校区/价格段，支持假分页和筛选）
```

### 3.3 stores/user.js（Pinia）

```text
state:   token('')、user(null)   —— 初始化时从 localStorage 读
getters: isLoggedIn、isAdmin(user?.role === 1)
actions: setLogin(token, user) 写 state + localStorage
         logout() 调 api 退出 + 清 state/localStorage + 跳登录页
```

### 3.4 constants/index.js

```text
PRODUCT_STATUS:  { 0:草稿, 1:待审核, 2:审核驳回, 3:在售, 4:已下架, 5:已售罄 } + 每个状态的 tag 颜色
ORDER_STATUS:    { 0:待卖家确认, 1:已确认, 2:已完成, 3:已取消, 4:超时取消, 5:纠纷中 } + 颜色
ITEM_CONDITION:  { 0:全新, 1:几乎全新, 2:轻微使用, 3:明显使用 }
DISPUTE_STATUS:  { 0:待处理, 1:待补充材料, 2:已驳回, 3:维持完成, 4:取消交易 }
DISPUTE_REASON:  { 0:货不对板, 1:未履约, 2:其他 }
CAMPUS_LIST:     校区列表（先写死数组，如 ['东校区','西校区','南校区','北校区']）
```

## 4. 路由与页面清单

| 路径 | 组件 | 登录 | 说明 |
| --- | --- | --- | --- |
| /login | LoginView | 否 | 登录（含跳注册链接） |
| /register | RegisterView | 否 | 注册 |
| / | HomeView | 否 | 商品列表（首页） |
| /products/:id | ProductDetailView | 否 | 商品详情 |
| /publish | ProductEditView | 是 | 发布商品 |
| /products/:id/edit | ProductEditView | 是 | 编辑商品（同组件，按有无 :id 区分） |
| /my/products | MyProductsView | 是 | 我的商品管理 |
| /orders/create | OrderCreateView | 是 | 下单确认页（query: productId） |
| /my/orders | MyOrdersView | 是 | 我的订单（买/卖 tab） |
| /orders/:id | OrderDetailView | 是 | 订单详情 |
| /my/history | BrowseHistoryView | 是 | 浏览记录 |
| /admin/products | AdminProductReviewView | 管理员 | 商品审核 |
| /admin/disputes | AdminDisputeView | 管理员 | 纠纷处理 |

路由守卫：`meta.requiresAuth` 未登录 → 跳 /login?redirect=原路径；`meta.requiresAdmin` 非管理员 → 提示无权限跳首页。

## 5. 页面详细设计

### 5.1 LoginView / RegisterView
- el-card 居中表单。登录：account（学号或手机号）+ password；注册：studentNo/phone/password/确认密码/nickname/campus（下拉）。
- el-form rules 前端校验（必填、手机号格式、密码 8~20 位含字母数字、两次密码一致）。
- 登录成功：store.setLogin → 跳 redirect 或首页。注册成功：提示后跳登录页。

### 5.2 HomeView（商品列表）
- 顶部筛选区：关键词输入框（回车/按钮搜索）、分类（el-select，来自 GET /categories）、校区、价格区间（两个 input-number）、重置按钮。
- 商品网格：ProductCard × n（封面图、标题、价格红色加粗、校区+成色小字）。点击卡片跳详情。
- 底部 el-pagination；筛选条件变化重置到第 1 页。空结果显示 el-empty。

### 5.3 ProductDetailView
- 左：el-carousel 图片轮播；右：标题、价格、成色/校区/交易地点/库存/浏览次数、卖家信用卡片（昵称、信用分、成交数、好评率）。
- 最近评价列表（recentReviews）。
- 操作按钮逻辑：未登录 → "登录后购买"跳登录；自己的商品 → 显示"去管理"；否则"立即购买"跳 /orders/create?productId=xx。
- 404 时显示"商品不存在或已下架" el-result。

### 5.4 ProductEditView（发布/编辑共用）
- 表单：标题、描述（textarea）、价格、库存（el-input-number ≥1）、成色/分类/校区（select）、交易地点、图片（ImageUploader，最多 5 张）。
- 编辑模式：进入时按 :id 拉详情回填；提交带 version；409 时提示刷新。
- 提交成功 → 跳 /my/products 并提示"已保存为草稿，请申请上架"。

### 5.5 MyProductsView
- el-table 或卡片列表：封面、标题、价格、库存、状态 tag、按状态显示操作按钮：
  - 草稿/驳回/已下架：编辑、申请上架、（驳回时展示驳回原因 tooltip）
  - 待审核：撤回申请
  - 在售：下架、调库存（el-popover 里 +/- delta）
  - 已售罄：无操作（提示等待取消回补或下架）
- 状态筛选 tab。所有操作后刷新列表。

### 5.6 OrderCreateView
- 展示商品摘要（标题/价格/库存）+ 表单：数量（≤库存）、交易时间（el-date-picker）、交易地点（默认商品的）、备注。
- **requestId：进入页面时 crypto.randomUUID() 生成一次存 ref，提交失败重试不重新生成**。
- 金额实时计算展示。提交成功 → 跳订单详情。429 提示"操作太频繁"；409 提示"库存不足或商品已变化"并刷新商品信息。

### 5.7 MyOrdersView
- el-tabs：我买到的（role=buyer）/ 我卖出的（role=seller）；内嵌状态筛选。
- 每行：快照标题+价格、数量、总额、OrderStatusTag、对方昵称、创建时间，点击跳订单详情。

### 5.8 OrderDetailView（状态机操作核心页）
- 区块：订单信息（订单号、状态、时间线）、商品快照卡片（标题/图/价格，注明"下单时快照"）、交易约定（时间/地点/备注）、双方信息、状态日志时间线（el-timeline）。
- 操作按钮**完全由后端 can* 字段驱动**：canConfirm→确认订单（卖家）、canCancel→取消（弹窗填原因）、canComplete→确认完成（买家，el-popconfirm）、canReview→去评价（弹 dialog：评分 el-rate + 内容 + 标签）、canDispute→发起纠纷（dialog：原因类型 select + 陈述 textarea + 证据 ImageUploader）。
- 任何操作 409 → 提示"订单状态已变化"并刷新页面数据。

### 5.9 BrowseHistoryView
- ProductCard 列表 + 最后浏览时间，分页。

### 5.10 AdminProductReviewView
- 待审核商品 el-table：标题、卖家、价格、提交时间；展开行或 dialog 看完整信息+图片。
- 操作：通过（直接确认）/ 驳回（必填原因 textarea）。

### 5.11 AdminDisputeView
- 状态筛选 + el-table：订单号、申请人、被投诉方、原因类型、状态、创建时间。
- 详情 dialog：订单快照、双方信息、申请陈述、证据图片（el-image 预览）、处理表单——动作 radio（驳回/维持完成/取消交易/待补材料）+ 取消交易时勾选"回补库存" + 处理说明。

## 6. App.vue 全局布局

- 顶栏（el-menu horizontal 或自定义 header）：Logo（点击回首页）、搜索框（回车带 keyword 跳首页）、右侧：
  - 未登录：登录 / 注册按钮
  - 已登录：发布闲置按钮（高亮）、头像下拉（我的商品/我的订单/浏览记录/退出登录），管理员多显示"后台管理"入口
- 内容区：`<router-view>`，宽度 max-width 1200px 居中。
- 不做移动端适配（第一版桌面优先）。

## 7. 开发顺序建议（对应方案 D2~D3）

```text
1. 基础件：request.js → constants → user store → router → App.vue 布局
2. mock 数据：product / auth / order 三个先造
3. 认证页：Login / Register
4. 商品侧：Home → ProductDetail → ProductEdit → MyProducts
5. 交易侧：OrderCreate → MyOrders → OrderDetail（含评价/纠纷 dialog）
6. 收尾：BrowseHistory → 两个 Admin 页
每完成一步在浏览器里点一遍再继续。
```

## 8. 给 AI 的施工提示（在 VS Code 里用）

把本文档 + API接口文档.md 一起给 AI，并按第 7 节顺序**一次只让它做一步**（如"先生成 request.js 和 constants"），每步你跑通看过再继续。要求它：
- 严格按 API 文档字段命名，不自创字段；
- 组件用 `<script setup>`；
- 不引入文档之外的新依赖；
- mock 与真实请求的切换只通过 VITE_USE_MOCK，页面代码无感知。
