> 目标：把简历项目一落地成"能跑、能演示、能讲清"的全栈项目，并通过全过程掌握标准的开发与部署操作。
>
> v2 变化：① 吸收已确定的共识（AI 辅助下约 1 周完成、先前端后后端、你自己搭环境 AI 辅助写码）；② 开发流程改为"契约驱动 + 前端先行"；③ 每个阶段增加「验收标准」和「你必须能讲清的点」；④ 补充 Git 工作流、多环境配置、常见坑清单和上云安全清单。

> 配套文件（已在 campus-trade/ 下）：`deploy/sql/init.sql`（建表）、`docs/API接口文档.md`（前后端契约，开发期间的唯一事实源）。

## 0. 部署路线：本地 Docker → 云服务器（不是二选一）

| | 本地 Docker Compose | 云服务器 |
| --- | --- | --- |
| 成本 | 0 元 | 学生机约 100 元/年（2C2G 够用） |
| 作用 | 开发期跑 MySQL/Redis；验证整套部署配置 | 公网地址可写进简历；体验真实运维 |
| 学到 | Docker、Compose、容器网络、环境变量 | Linux、Nginx、防火墙/安全组、上线流程 |

关键认知：**compose 写好后，本地和云跑的是同一份文件**。本地跑通 = 部署完成 90%，上云只是换台机器执行 `docker compose up -d` 再配防火墙。

## 1. 整体架构（第一版）

```text
浏览器
  ▼
Nginx（80）
  ├── /        → 前端静态文件（Vue 3 打包产物）
  └── /api/**  → 反代后端 8080
                    │
              Spring Boot 单体
                    ├── MySQL 8（事实数据）
                    ├── Redis 7（登录态/详情缓存/防抖）
                    └── 本地磁盘 volume（图片，抽象 FileStorageService，第二步可换 OSS）
```

第一版不引入 RocketMQ：超时关单用定时扫表（简历文档本身认可"扫表是第一版/兜底"）；第二步换"延迟消息为主 + 扫表兜底"——这个演进就是现成的面试叙事。

## 3. 开发工作流（v2 核心：契约驱动 + 前端先行）

分工共识：**你亲手搭环境、建工程、跑起来每一步；AI 在 VS Code 里辅助写代码**。写完每个模块，你要做三件事：跑起来、按验收标准点一遍、给自己讲一遍核心链路（讲不出来就让 AI 讲到你能复述）。

```text
阶段A 设计（已完成）：建表 SQL + API 契约
阶段B 前端开发（mock 模式）：
    契约 → mock 数据 → 全部页面完成，VITE_USE_MOCK=true 下整站可点
阶段C 后端开发：
    按同一份契约逐模块实现，用 Apifox/Postman 自测每个接口
阶段D 联调：
    关 mock 开关 → 逐页面过一遍 → 修字段/格式偏差
阶段E 部署：
    Dockerfile ×2 + compose 全量 → 本地整站跑通 → 上云
```

契约纪律（重要）：开发中发现契约不合理，**先改 `docs/API接口文档.md`，再改代码**。前后端所有字段、格式争议都以文档为准，这是多人协作的真实工作方式。

### Git 工作流（从第一天开始练）

- 本地建仓（是否推 GitHub 由你决定，不影响流程）：`git init` → 每完成一个小功能一次 commit。
- Commit message 格式：`feat: 登录接口`、`fix: 订单状态码写反`、`chore: 补充 compose 配置`。
- 练习分支：每个阶段开一个分支（如 `feat/frontend-pages`），完成后合回 main。面试可讲。

### 多环境配置（从第一天就分开）

| 端 | 开发 | 生产 |
| --- | --- | --- |
| 后端 | `application-dev.yml`（连 localhost 的 Docker MySQL/Redis） | `application-prod.yml`（连服务名 mysql/redis，密码走环境变量） |
| 前端 | `.env.development`（VITE_USE_MOCK 开关 + Vite proxy /api→8080） | `.env.production`（走 Nginx 同域 /api） |

密钥（JWT secret、数据库密码）一律环境变量注入，绝不进代码和 Git。

## 5. 阶段计划（AI 辅助节奏，约 7 个工作日）

> 时间只是参考，硬性要求是每阶段末尾的「验收」全部通过再进下一阶段。

### D1 环境 + 前端骨架
- 装 Docker Desktop / JDK17 / Node20；`docker compose up mysql redis`；执行 init.sql 确认 12 张表建好。
- Vite 创建前端工程，接入 Element Plus / Pinia / Router；写好 `utils/request.js`（统一 code 处理 + 401 跳登录）、`constants/`、路由骨架和布局（顶栏 + 登录态展示）。
- **验收**：`npm run dev` 打开空壳站点，能在登录/列表等空页面间跳转。
- **必须能讲清**：Vite proxy 解决什么问题（开发期跨域）；token 为什么存 Pinia + localStorage 各一份。

### D2~D3 前端全部页面（mock 模式）
- 11 个页面全部完成：登录注册、商品列表/详情、发布编辑、我的商品、下单确认、我的订单（买/卖 tab）、订单详情（快照+日志+按钮）、评价、浏览记录、管理员（审核+纠纷）。
- mock 数据按 API 文档 1:1 编写；订单详情页按钮直接绑定 `can*` 字段。
- **验收**：mock 模式下整站每个页面可点、每个状态有对应展示（用 mock 造出 6 种订单状态各一单）。
- **必须能讲清**：路由守卫怎么拦未登录；Axios 拦截器做了什么；分页组件数据流。

### D4~D5 后端核心闭环
- D4：common/config 基础件 → 认证模块（注册/登录/退出/拦截器/UserContext）→ 类目/文件上传 → 商品模块（发布/编辑/上下架/审核/列表/详情）。
- D5：订单模块（防抖 + requestId 幂等 + 条件更新扣库存 + 快照 + 日志同事务）→ 状态机（确认/取消/完成）→ 定时扫表超时关单 → 评价 + 信用摘要 → 纠纷。
- 每写完一个模块立即用 Apifox 自测，不要攒到最后。
- **验收（用 Apifox 走通即可，不依赖前端）**：注册→登录→发布→审核→下单→确认→完成→评价 全链路 2xx；重复 requestId 返回同一订单；两个账号并发买库存 1 的商品只成功一单；改短 confirm_deadline 验证超时关单生效。
- **必须能讲清**：JWT+Redis 双层登录态为什么两个都要；条件更新扣库存为什么防超卖；快照解决什么问题；@Transactional 失效的 4 个场景。

### D6 联调 + 缓存
- 关 mock，逐页联调修偏差（重点：Long 精度、时间格式、分页字段名）。
- 加商品详情 Redis 缓存 + 空值缓存 + afterCommit 删缓存；浏览记录 upsert。
- **验收**：真实前后端走通 D5 的全链路；redis-cli 能看到 `product:detail:*` 命中与失效。
- **必须能讲清**：为什么删缓存不更新缓存；空值缓存防什么；afterCommit 解决什么。

### D7 部署
- 上午本地：backend 多阶段 Dockerfile（maven→JRE）、frontend Dockerfile（node build→nginx）、compose 全量 4 服务 + healthcheck + depends_on；`docker compose up -d --build` 整站跑通。
- 下午上云：买 2C2G Ubuntu 22.04 学生机 → 装 Docker → scp/git 拉项目 → 改 .env → up -d → 公网 IP 访问。
- **上云安全清单**：安全组只开 22/80；SSH 改密钥登录、禁密码；MySQL/Redis 端口**不映射到宿主机公网**（仅 compose 内网）；所有默认密码改强密码；.env 不进 Git。
- **验收**：手机流量（非同一 WiFi）访问公网 IP 完成一单完整交易。
- **必须能讲清**：镜像/容器/volume 区别；容器间为什么用服务名互访；Nginx 反代配置每行含义；多阶段构建为什么镜像小。

### 第二步迭代（简历增强，各自独立可做）
1. RocketMQ 延迟关单（保留扫表做兜底）+ 信用重算异步化；
2. Redisson 互斥重建 + Caffeine 热点二级缓存；
3. JMeter 压测商品详情（冷缓存 vs 命中对照，留报告截图）；
4. GitHub Actions 自动构建镜像推服务器（体验 CI/CD）；
5. 域名 + HTTPS（Let's Encrypt）。

## 6. 常见坑预警（新手第一次全栈几乎都会踩）

| 坑 | 预防 |
| --- | --- |
| 跨域 CORS 报错 | 开发期一律走 Vite proxy，不要在后端到处加 @CrossOrigin |
| 订单 ID 精度丢失 | 后端 Long 全局序列化为字符串（Jackson 配置一处搞定） |
| 时间差 8 小时 | JVM、MySQL 连接串 serverTimezone、Docker 容器时区三处统一 Asia/Shanghai |
| 容器里连不上数据库 | 容器互访用服务名不用 localhost；等 MySQL healthcheck 通过再起后端 |
| mock 和真实接口字段对不上 | mock 严格按 API 文档写，联调偏差先改文档再改代码 |
| 图片上传后容器重启丢失 | uploads 目录挂 volume |
| Windows 换行符/权限问题 | Git 配 `core.autocrlf=input`；shell 脚本在服务器上跑不要在 Windows 改 |

## 7. 第一版明确不做（面试也这么讲）

支付/退款/物流（平台定位是信息撮合+线下面交）、RocketMQ（第二步）、Caffeine/ES/微服务（第二步或不做）、阿里云 OSS（接口已抽象，第二步可换）。

## 8. 现在就可以开始

1. 你在本机装好 Docker Desktop、JDK 17、Node 20、VS Code（+IDEA 可选）。
2. 从 D1 开始：起 MySQL/Redis 容器 → 执行 init.sql → 创建前端工程。
3. 每一步卡住随时把报错发我；每个阶段验收完成后告诉我，我们再进下一阶段。
