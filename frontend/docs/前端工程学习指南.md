## 第一部分　宏观认知：前端工程到底是什么

### 1.1 前后端各自负责什么（用后端视角类比）

| 关注点 | 后端（你熟悉的） | 前端（本项目） |
|---|---|---|
| 运行环境 | JVM / 服务器进程 | 用户的**浏览器** |
| 入口 | `main()` / Spring Boot 启动类 | `src/main.js` |
| 路由分发 | `@RequestMapping` 把 URL 映射到 Controller | `vue-router` 把 URL 映射到「页面组件」 |
| 分层 | Controller → Service → Mapper | 页面(View) → 接口层(api) → 请求封装(request) |
| 全局状态 | 单例 Bean / 缓存 | Pinia store（如登录态） |
| 数据模型 | Entity / DTO | 就是普通 JS 对象 |
| 权限拦截 | 拦截器 / Filter | 路由守卫 `router.beforeEach` |
| 统一异常处理 | `@ControllerAdvice` | Axios 响应拦截器 `request.js` |

**一句话**：前端就是一个「跑在浏览器里、根据 URL 渲染不同界面、通过 HTTP 找后端要数据」的程序。它同样讲分层、讲复用、讲统一处理，只是运行在浏览器、渲染的是界面而不是返回 JSON。

### 1.2 Vue 项目的运行原理（SPA + 构建）

本项目是 **SPA（单页应用，Single Page Application）**：整个网站其实只有一个 HTML 文件（`index.html`），里面只有一个空的 `<div id="app">`。所有界面都由 JavaScript 动态渲染进这个 div，切换页面时**不刷新浏览器**、不重新请求 HTML，只是 JS 把 div 里的内容换掉 —— 所以体验很流畅。

- **开发时**：运行 `npm run dev`，Vite 启一个本地开发服务器（默认 `http://localhost:5173`），你改代码浏览器自动热更新（HMR）。
- **上线时**：运行 `npm run build`，Vite 把所有 `.vue`/`.js`/`.css` 打包压缩成浏览器能直接跑的静态文件（`dist/` 目录），丢到任意静态服务器（Nginx 等）就能访问。

> 为什么需要「构建」？因为浏览器看不懂 `.vue` 文件，也看不懂 `import '@/xxx'` 这种写法。Vite 负责把这些「开发时的方便写法」翻译成「浏览器能懂的原生 JS/CSS」。这一步类比后端的「编译打 jar 包」。

### 1.3 技术栈全景（每个东西是干嘛的）

看 `package.json` 的 `dependencies`，逐个对号入座：

| 库 | 作用 | 后端类比 |
|---|---|---|
| **vue** | 核心框架：把「数据」和「界面」绑定起来，数据变界面自动变 | 类似模板引擎 + 响应式 |
| **vite** | 构建工具 + 开发服务器（在 devDependencies） | Maven/Gradle + 内置 tomcat |
| **vue-router** | 前端路由：URL ↔ 页面组件 | Spring MVC 的 URL 映射 |
| **pinia** | 全局状态管理：跨页面共享数据（登录态） | 全局单例/会话缓存 |
| **element-plus** | 现成 UI 组件库（按钮/表单/表格/弹窗…） | 一套现成的「界面积木」 |
| **@element-plus/icons-vue** | 配套图标 | — |
| **axios** | 发 HTTP 请求的库 | RestTemplate / OkHttp |

devDependencies 里的 `eslint`/`oxlint`/`prettier` 是**代码规范工具**：ESLint 查语法/潜在 bug，Prettier 统一格式（缩进/引号/分号）。对应后端的 Checkstyle/Spotless。

## 第二部分　新建 Vue 工程后的第一步（工程搭建顺序）

这一部分回答你的核心问题：**「Vue 工程建好后要怎么开始？我最早搭的基础件是什么？」**

### 2.1 工程是怎么建出来的

官方脚手架一条命令：

```bash
npm create vue@latest
```

它会交互式问你要不要 Router、Pinia、ESLint、Prettier 等，勾选后自动生成骨架。本项目就是这么来的：勾了 Router + Pinia + ESLint + Prettier。生成后 `npm install` 装依赖，`npm run dev` 就能跑起一个默认欢迎页。

> 脚手架生成的默认文件里，有些是示例（如 `src/stores/counter.js`、默认的 `HomeView` 欢迎页），后续会被我们真正的业务代码替换。`counter.js` 就是官方留下的 Pinia 示例，本项目没用到，你能看到它躺在那当参考。

### 2.2 目录结构规划（本项目实际结构）

```
frontend/
├─ index.html            # 唯一的 HTML，里面只有 <div id="app">
├─ package.json          # 依赖清单 + 脚本命令（dev/build/lint/format）
├─ vite.config.js        # 构建配置（关键：@ 别名指向 src）
├─ .env.development      # 开发环境变量（VITE_USE_MOCK=true 就在这）
└─ src/
   ├─ main.js            # 【入口】装配 Vue + 插件，挂载到 #app
   ├─ App.vue            # 【根组件】全局布局：顶栏 + <router-view>
   ├─ router/            # 【路由】URL→页面 映射表 + 权限守卫
   ├─ stores/            # 【全局状态】Pinia：登录态 user.js
   ├─ utils/             # 【工具】request.js = Axios 统一封装
   ├─ constants/         # 【常量】状态枚举中文/颜色映射
   ├─ api/               # 【接口层】每个业务模块一个文件，页面只调这里
   ├─ mock/              # 【假数据层】后端没好之前模拟接口返回
   ├─ components/        # 【可复用组件】卡片/上传器/状态标签
   └─ views/             # 【页面组件】每个路由对应一个，是「页面」
```

**记住一个分层原则（本项目最重要的架构）**：

```
页面(views) → 接口层(api) → 请求封装(utils/request) → 后端
                    ↘ 或 → mock（假数据）
```

页面**永远不直接** `import axios`，只调用 `src/api/` 里的函数。这样「要不要带 token、错误怎么弹、走 mock 还是真后端」这些都只在底层写一次，页面保持干净。这跟后端「Controller 不直接写 SQL，而是调 Service」是完全一样的思想。

### 2.3 最早该搭的「基础件」及顺序

这是我实际搭这个项目时的顺序，也是推荐你以后自己搭项目的顺序 —— **先修地基（公共设施），再盖楼（业务页面）**：

**① 配置层：`vite.config.js` 的 `@` 别名**
```js
resolve: { alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) } }
```
配了这个，任何文件里都能用 `@/api/product` 代表 `src/api/product`，不用写一串 `../../../`。这是第一件要做的小事，之后所有 import 都依赖它。

**② 环境变量：`.env.development`**
```
VITE_USE_MOCK=true
```
Vite 约定：以 `VITE_` 开头的变量能在代码里用 `import.meta.env.VITE_USE_MOCK` 读到。这个开关决定「走假数据还是真后端」，是本项目能「前端先独立开发、后端好了再无缝联调」的关键。

**③ 入口装配：`src/main.js`**（打开看，只有 19 行，但非常重要）
```js
const app = createApp(App)
app.use(createPinia())   // 注册状态管理（必须在用到 store 前）
app.use(router)          // 注册路由
app.use(ElementPlus, { locale: zhCn })  // 注册 UI 库 + 中文包
app.mount('#app')        // 把整个应用塞进 index.html 的 #app
```
这就是整个前端的「启动类」。所有全局插件都在这里 `app.use(...)` 装上。类比 Spring Boot 启动时装配各种 Bean。

**④ 常量层：`src/constants/index.js`**
把「状态数字 → 中文label + 颜色」的映射集中定义（商品/订单/纠纷状态）。为什么最早做？因为几乎每个页面都要显示状态标签，集中一处维护，改文案不用满项目找。这体现一个好习惯：**魔法数字/重复文案要收敛到常量层**。

**⑤ 全局状态：`src/stores/user.js`**（登录态）
```js
export const useUserStore = defineStore('user', () => {
  const token = ref(localStorage.getItem('ct_token') || '')  // 刷新不丢
  const user  = ref(JSON.parse(localStorage.getItem('ct_user') || 'null'))
  const isLoggedIn = computed(() => !!token.value)
  const isAdmin    = computed(() => user.value?.role === 1)
  function setLogin(t, u) { /* 写内存 + 写 localStorage */ }
  function clearLogin()   { /* 两边都清 */ }
  return { token, user, isLoggedIn, isAdmin, setLogin, clearLogin }
})
```
为什么早做？因为**请求封装要读 token、路由守卫要判断登录、顶栏要显示用户** —— 三个基础件都依赖它。
关键点：数据同时存「内存(ref)」和「localStorage」。内存里的 ref 是**响应式**的（变了界面立刻更新），localStorage 保证**刷新页面登录态不丢**（浏览器刷新会清空 JS 内存，但 localStorage 还在，所以初始化时从它恢复）。

**⑥ 请求封装：`src/utils/request.js`**（全项目唯一发 HTTP 的地方，务必读透）
它做了三件后端里「拦截器 + 全局异常处理」干的事：
- **请求拦截器**：每个请求自动带上 `Authorization: Bearer <token>`（从 store 读）。
- **响应拦截器**：后端统一返回 `{ code, message, data }`。`code===0` 只把 `data` 交给页面（页面拿到的直接是数据，不用层层剥）；`code===401` 自动清登录态跳登录页；其他错误码**统一弹 `ElMessage.error`**，所以页面 `catch` 里不用再弹一遍。
- 对外只导出 `get/post/put/del` 四个语义化方法，接口层只用这几个。

> 这是「统一处理只写一次」的典范。理解了它，你就理解了为什么页面代码可以那么短。

**⑦ mock 层 + 接口层：`src/mock/` 与 `src/api/`（成对出现）**
每个业务模块（auth/product/order…）都有一对：
- `src/mock/xxx.js`：用 JS 内存数组模拟后端的数据和业务规则（含校验、延迟、失败）。
- `src/api/xxx.js`：页面唯一入口。内部靠开关切换：
```js
const useMock = import.meta.env.VITE_USE_MOCK === 'true'
export function login(data) {
  if (useMock) return mockLogin(data)   // 假数据
  return post('/auth/login', data)      // 真后端
}
```
**这套双层是本项目的精髓**：前端不用等后端就能把全部功能做完、测完；后端 API 一好，只把 `.env` 的 `VITE_USE_MOCK` 改成 `false`，页面代码一行不改就切到真实联调。

**⑧ 路由 + 守卫：`src/router/index.js`**
- 路由表：`{ path: '/products/:id', component: () => import('@/views/ProductDetailView.vue') }`。`:id` 是**动态参数**；`() => import(...)` 是**懒加载**（访问到才下载那个页面的 JS，首屏更快）。
- 全局守卫 `beforeEach`：每次跳转前检查 `meta.requiresAuth` / `meta.requiresAdmin`，没登录踢去登录页（并用 `redirect` 记住原目标），非管理员访问 admin 页踢回首页。
- ⚠️ 注释里特别强调：**前端守卫只是体验层拦截，真正的权限校验必须在后端**（前端代码用户能改，不可信）。这条安全意识要记牢。

**⑨ 根布局：`src/App.vue`**
所有页面共用的外壳：顶栏（Logo、登录/注册 或 发布+头像菜单）+ `<router-view>`（当前 URL 对应的页面渲染在这里）。

**⑩ 打通第一个闭环：登录页 `src/views/LoginView.vue`**
地基搭好后，第一个业务页选「登录」最合适 —— 它能把上面所有基础件串起来验证一遍：表单校验 → 调 `api/auth` → 写 `store` → 跳转。跑通它 = 证明地基没问题，之后就能放心一个个加业务页面了。

> **总结这个顺序的逻辑**：配置 → 入口 → 被最多人依赖的公共件（常量、登录 store、请求封装）→ 数据来源（mock+api）→ 路由 → 布局 → 第一个页面闭环。永远是「越底层、越被依赖的越先搭」。

## 第三部分　核心概念逐个击破（配本项目代码）

### 3.1 组件与单文件组件（SFC）

一个 `.vue` 文件就是一个「组件」，三段式结构：
```vue
<script setup>  // JS 逻辑：数据、方法、生命周期
</script>
<template>      // HTML 模板：界面长什么样
</template>
<style scoped>  // CSS 样式；scoped = 只作用于本组件，不污染别处
</style>
```
`<script setup>` 是 Vue 3 的推荐写法：在里面声明的变量/函数，模板里能直接用，不用额外导出。
组件分两类（本项目）：`views/` 里的是「页面级组件」（对应一个路由），`components/` 里的是「可复用组件」（被多个页面拼装使用）。

### 3.2 响应式：`ref` / `reactive` / `computed`（前端的灵魂）

前端和后端最大的思维差异在这：**你不用手动操作界面，只要改数据，界面自己变**。前提是数据得是「响应式」的。

- `ref(初始值)`：包装单个值，**读写要加 `.value`**（模板里自动解包不用写）。
  ```js
  const loading = ref(false)
  loading.value = true       // 改它，绑定它的界面自动更新
  ```
- `reactive({...})`：包装一个对象，直接 `obj.field` 读写（不用 `.value`）。本项目表单、筛选条件用它：
  ```js
  const form = reactive({ account: '', password: '' })
  form.account = '20230001'  // 界面同步变
  ```
- `computed(() => ...)`：**派生值**，依赖的数据变了它自动重算。如 `user.js` 里：
  ```js
  const isLoggedIn = computed(() => !!token.value)  // token 一变，它自动跟着变
  ```
  下单页「应付金额 = 单价 × 数量」也是 computed：数量一改金额自动重算。

> 记忆口诀：**单个值用 `ref`（记得 `.value`），一组值用 `reactive`，算出来的值用 `computed`。**

### 3.3 模板语法（`template` 里的特殊写法）

打开 `LoginView.vue` 的 template 对照：
- `{{ 变量 }}`：插值，把数据显示到界面。
- `v-model="form.account"`：**双向绑定** —— 输入框内容 ↔ 变量，用户输入变量自动变，代码改变量输入框也变。表单必用。
- `:属性="变量"`（如 `:loading="loading"`）：**单向绑定**，把变量值传给组件属性（`:` 是 `v-bind` 简写）。
- `@事件="方法"`（如 `@click="onSubmit"`、`@keyup.enter="onSubmit"`）：**绑定事件**（`@` 是 `v-on` 简写）。
- `v-if="条件"`：条件渲染，false 时元素不存在。App.vue 顶栏用它区分「登录/未登录」两套按钮。
- `v-for="item in list" :key="item.id"`：**列表渲染**，循环生成元素。首页商品网格、订单表格都靠它。`:key` 给每项唯一标识（帮 Vue 高效更新，必须写）。

### 3.4 组件通信：`props` / `v-model` / `emit`

组件之间怎么传数据？看两个真实例子：

- **父传子：`props`（只读）** —— `ProductCard.vue` 接收父页面传来的商品对象：
  ```vue
  <!-- 父：首页 --> <ProductCard :product="item" />
  <!-- 子：ProductCard 里 --> const props = defineProps({ product: Object })
  ```
  子组件不能直接改 props（单向数据流：数据从父流向子）。

- **子传父：`emit`（发事件）** + **`v-model`（双向的语法糖）** —— `ImageUploader.vue` 是可被 `v-model` 绑定的组件：
  ```vue
  <!-- 父：发布页 --> <ImageUploader v-model="form.images" />
  ```
  父用 `v-model` 绑一个数组，子组件内部图片增删后，通过 `emit('update:modelValue', 新数组)` 通知父更新。这样「一个上传组件」能被发布页、纠纷证据等多处复用。

### 3.5 生命周期：`onMounted`

组件有「诞生→更新→销毁」的生命周期钩子。最常用的是 `onMounted`：**组件挂载到页面后执行**，通常用来「进页面就去加载数据」。看 `HomeView.vue`：
```js
onMounted(async () => {
  filters.keyword = route.query.keyword || ''
  await Promise.all([getCategories(), loadProducts()])  // 进首页就并行拉分类+商品
})
```
类比：像 Controller 方法进来先查数据库准备数据。`Promise.all([...])` 表示两个请求**并行**发（而不是一个等一个），页面出得更快。

### 3.6 路由进阶（`vue-router`）

- **动态路由参数**：`/products/:id`，页面里用 `route.params.id` 取到具体 id。
- **查询参数**：`/?keyword=手机`，用 `route.query.keyword` 取。
- **编程式导航**：`router.push('/login')` 或 `router.push({ path:'/', query:{ keyword:'x' } })` 跳转。
- **拿路由信息 vs 操作路由**：`useRoute()` 读当前路由（只读），`useRouter()` 拿到 router 去跳转。别搞混。
- **守卫**：见 2.3 第⑧点。登录被拦时把目标塞进 `redirect`，登录成功后 `LoginView` 用 `router.push(route.query.redirect || '/')` 跳回去 —— 一个很常见的体验细节，值得学。

### 3.7 全局状态：Pinia（`stores/user.js`）

什么时候用 store？**多个互不相邻的组件都要用同一份数据**时。本项目就登录态一个：顶栏、路由守卫、请求拦截器、各页面都要知道「谁登录了」，所以放 store。
用法：任意组件里 `const userStore = useUserStore()`，然后 `userStore.isLoggedIn` / `userStore.setLogin(...)`。
不适合放 store 的：只有单个页面用的临时数据（放页面自己的 `ref` 就行）。

### 3.8 异步与请求（`async/await` + Promise + 拦截器）

前端拿后端数据是**异步**的（发出去要等）。统一用 `async/await`：
```js
async function onSubmit() {
  loading.value = true
  try {
    const data = await login({ account, password })  // 等接口返回
    userStore.setLogin(data.token, data.user)
    router.push('/')
  } catch {
    // 失败：错误提示已由 request.js 统一弹了，这里不用重复弹
  } finally {
    loading.value = false   // 无论成败都关掉 loading，否则一直转圈
  }
}
```
配合 `request.js` 的响应拦截器（3.2 已讲），页面代码非常薄：**成功路径拿 data 用，失败路径只管收尾（关 loading），弹错交给底层。**

### 3.9 mock/api 双层（再强调一次，因为最重要）

以「商品列表」走一遍，把三个文件连起来看：
1. 页面 `HomeView.vue`：`import { getProducts } from '@/api/product'` → `await getProducts({...})`
2. 接口层 `api/product.js`：`useMock ? mockGetProducts(params) : get('/products', params)`
3. 假数据 `mock/product.js`：`mockGetProducts` 在内存数组里做筛选/分页，返回 `{ list, total, page, pageSize }`

未来后端好了：`.env` 改 `VITE_USE_MOCK=false`，第 2 步自动走 `get('/products', params)` → `request.js` → 真后端。**页面和接口层签名完全不变**。这就是为什么我们能「前端先行、后端后补、无缝切换」。

> 你会发现每个 `mock/xxx.js` 里都有 `delay()`（模拟网络延迟，好让 loading 效果看得见）和 `fail()`（模拟失败：弹提示 + reject，行为对齐 request.js）。这是为了让 mock 的体验尽量逼近真接口。

### 3.10 表单校验（Element Plus）

看 `LoginView.vue`：
```js
const rules = {
  account: [{ required: true, message: '请输入学号或手机号', trigger: 'blur' }],
}
// 提交前：
await formRef.value.validate()   // 不通过会抛异常中断，不会发请求
```
`el-form` 绑 `:rules`，每个 `el-form-item` 用 `prop` 关联字段。提交时先 `validate()` 过一遍前端校验，通过才发请求。`trigger:'blur'` = 失焦时校验。发布页 `ProductEditView.vue` 有更完整的多字段校验例子，学完登录页可以去看它。

## 第四部分　跟着数据流走一遍（把知识串起来）

光看零件不够，要看它们怎么协作。挑三条链路，**建议对着文件逐个跳转着读**。

### 4.1 登录闭环（最短，先看这条）

```
用户在 LoginView 输入并点「登录」
  → onSubmit(): formRef.validate() 前端校验
  → 调 api/auth.js 的 login()
  → useMock=true → mock/auth.js 的 mockLogin()：比对账号密码，返回 { token, user }
  → 回到 onSubmit：userStore.setLogin(token, user)  // 写 Pinia + localStorage
  → App.vue 顶栏因为 isLoggedIn 变 true，自动换成「头像菜单」（响应式的威力）
  → router.push(redirect || '/') 跳走
```
涉及文件：`LoginView.vue` → `api/auth.js` → `mock/auth.js` → `stores/user.js` → `App.vue`。把这条看懂，你就懂了「页面/接口/mock/store/路由」怎么配合。

### 4.2 首页商品列表闭环

```
进入首页 → HomeView 的 onMounted → Promise.all([getCategories(), loadProducts()])
  → loadProducts() 调 api/product.js 的 getProducts(筛选条件)
  → mock/product.js：按 关键词/分类/校区/价格 过滤 + 只留在售且有货 + 分页
  → 拿到 { list, total } → 存进 ref → template 用 v-for 渲染成一格格 ProductCard
用户改筛选点「搜索」→ onSearch() 回到第1页重新 loadProducts()
点某张卡片 → ProductCard 内 router.push(`/products/${id}`) → 进详情页
```
重点体会：**筛选/分页只是改变传给接口的参数，再重新渲染**，界面变化全靠数据驱动。

### 4.3 下单 → 订单详情 → 状态机（最复杂，放最后攻）

这条把「表单、幂等、状态机、权限显隐、时间线」全用上了：
```
商品详情点「立即购买」→ OrderCreateView：选数量(≤库存)/时间/地点/备注
  → 进页面只生成一次 requestId（防止重复提交下重单，幂等思想）
  → 应付金额 = 单价×数量（computed 实时算）
  → 提交 createOrder → mock/order.js：买自己商品→400、库存不足→409、成功扣库存并生成含「下单快照」的订单
  → 跳 /orders/:id
OrderDetailView：展示订单 + 状态时间线 + 按 canConfirm/canCancel/... 决定显示哪些操作按钮
  → 卖家「确认」(0→1)、买家「完成」(1→2)、双方「取消」(→3，回补库存)、「评价」、「发起纠纷」(→5)
  → 每次操作后刷新详情，时间线多一条流转记录
```
关键概念：
- **快照**：下单时把商品标题/价格拷进订单，之后卖家改商品不影响历史订单（对应后端会存订单明细）。
- **幂等 `requestId`**：同一次下单只创建一单，防手抖/网络重试下重单。
- **状态机**：订单状态只能按规定路径流转，非法流转 mock 返回 409。业务规则集中在 `mock/order.js` 的 `can*` 判断里。
- **按能力显隐按钮**：后端返回 `canConfirm/canCancel/...`，前端据此显示按钮 —— 前端负责体验，后端才是权限的最终裁判。

看懂这条，交易类系统的前端你就基本通了。

## 第五部分　延伸：联调真实后端与部署

等你后端 Spring Boot 写好后：
1. 把 `.env`（或新建 `.env.development`）里 `VITE_USE_MOCK` 改为 `false`。
2. 配置 API 代理：`request.js` 的 `baseURL` 是 `/api`，开发时可在 `vite.config.js` 加 `server.proxy` 把 `/api` 转发到后端端口（如 `http://localhost:8080`），避免跨域。
3. 逐个模块联调：登录 → 商品 → 订单 …，对照 `docs/API接口文档.md` 核对字段。哪个接口返回结构和 mock 不一致，就在对应 `api/xxx.js` 里适配。
4. 上线：`npm run build` 产出 `dist/`，用 Nginx 托管静态文件并反代 `/api` 到后端；或按你的规划用 Docker Compose 把「前端(Nginx) + 后端 + MySQL + Redis」一起编排。

> 你会切身体会到当初 mock/api 双层的价值：切后端时页面代码几乎不用动，改的都在接口层。这就是「面向接口编程」在前端的体现。

### 结语

前端的核心心智模型其实就三句话：
1. **数据驱动界面**（改数据，界面自己变 —— 响应式）；
2. **分层复用**（页面 → 接口层 → 请求封装，公共逻辑只写一次）；
3. **URL 驱动页面**（路由把 URL 映射到组件，守卫做拦截）。
